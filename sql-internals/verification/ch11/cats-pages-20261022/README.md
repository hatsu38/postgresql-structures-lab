# 第11章：cats の UPDATE・VACUUM 前後のページの中身と、作り方によるページ数の違い

2026-10-22に実施。第11章の脚注「1万8,000件を第10章の『1ページ約156件』で割ると約115ページになり、実際の99ページと合いません」の根拠にした。`cats-vacuum-20261019` はページ数だけを記録していたので、この記録では、ページの中に何が入っていたかを `pageinspect` で直接読んだ。あわせて、同じデータを `CREATE TABLE ... AS`・`INSERT`・`COPY` で入れたときのファイルのページ数を比べた。

## 環境

- 手元の Mac に作った一時クラスタ（PostgreSQL 18.3、Homebrew、aarch64-apple-darwin25.2.0）。測定後に停止して、データを捨てた。
- `autovacuum=off`、`max_parallel_workers_per_gather=0`、`jit=off`、block_size=8192。
- データベース名は `reading_map`。`pageinspect` と `pg_visibility` の拡張を使うので、スーパーユーザーで実行する。
- 他のディレクトリの測定は PostgreSQL 18.6（Docker）なので、環境が違う。同じ作り方の `cats` の値（64ページ、UPDATE 後に99ページ、VACUUM で81ページが all-visible）は、`cats-vacuum-20261019` の記録と一致した。

## 再現手順

```sh
psql -X -a -U postgres -d reading_map < observe.sql > observe.log 2>&1
```

`COPY` の比較では、`/tmp/cats-pages-copy.csv` を一時的に作り、最後に消す。

## 確認した結果（observe.log）

`cats` を `CREATE TABLE ... AS` で作り、8,000匹を UPDATE して、VACUUM した。

| 観察 | 値 |
| --- | --- |
| 作成直後のファイルのページ数 | 64 |
| 作成直後にレコードが入っているページ数 | 45（ページ0〜44） |
| 作成直後のページ0・ページ63のレコード数 | 226・0 |
| UPDATE 後のファイルのページ数 | 99 |
| UPDATE 後：元のレコードのページ | ページ0〜44（45ページ、10,000件。更新された8,000件の元のレコードと、更新していない2,000件） |
| UPDATE 後：空のページ | ページ45〜62（18ページ） |
| UPDATE 後：新しいレコードが入ったページ | ページ63〜98（36ページ、8,000件） |
| VACUUM 後のファイルのページ数 | 99（`0 removed`） |
| VACUUM で all-visible の印が付いた・付かなかったページ数 | 81・18 |
| 印が付かなかったページ | ページ45〜62（18ページ。レコードは0件） |

45 ＋ 18 ＋ 36 ＝ 99 になる。1万件が45ページに収まるので、1ページには226件入る。第10章の「1ページ約156件」は、空のページも含めて 10,000 ÷ 64 で割った平均である。

作り方とサイズによる、ファイルのページ数とレコードが入ったページ数（同じ2列、`id` と `'A'`）：

| 件数 | 作り方 | ファイルのページ数 | レコードが入ったページ数 | 空のページ |
| ---: | --- | ---: | ---: | ---: |
| 1,000 | CREATE TABLE AS | 8 | 5 | 3 |
| 1,000 | COPY | 5 | 5 | 0 |
| 1,000 | INSERT | 5 | 5 | 0 |
| 10,000 | CREATE TABLE AS | 64 | 45 | 19 |
| 10,000 | COPY | 80 | 45 | 35 |
| 10,000 | INSERT | 45 | 45 | 0 |
| 100,000 | CREATE TABLE AS | 448 | 443 | 5 |
| 100,000 | COPY | 464 | 443 | 21 |
| 100,000 | INSERT | 443 | 443 | 0 |
| 1,000,000 | CREATE TABLE AS | 4,480 | 4,425 | 55 |
| 1,000,000 | COPY | 4,432 | 4,425 | 7 |
| 1,000,000 | INSERT | 4,425 | 4,425 | 0 |

`INSERT` は、必要なページ数ぴったりになった。`CREATE TABLE AS` と `COPY` は、最後に空のページが付くことがあり、その数は件数に比例しなかった（今回の範囲では 0〜55ページ）。

## 確認できていないこと

- PostgreSQL 15 以前では測っていない。PostgreSQL 16 のリリースノートに、「ヒープとインデックスのページを効率よく追加できるようにした」という項目があり、そのコミットの説明では、それまでは1ページずつ足していたとされている。空のページが付くのは、この変更によるものと考えられるが、ソースコードまでは読んでいない。
- 余った空のページの数を、どう決めているかは調べていない。
- 初めの試行では、UPDATE の直後に `SELECT ... FROM cats WHERE id = 1` を挟んだところ、元のレコードしかないはずのページ0〜34が空に見えた。全件を読む問い合わせが、元のレコードを片付けた（ページの枝刈り）ためと考えられる。そのため、UPDATE の直後は `pageinspect` でページを直接読むだけにして、全件を読む問い合わせは VACUUM のあとに置いた。
